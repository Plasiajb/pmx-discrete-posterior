## Acceptance Change

The earlier route stopped at a precision-limited gradient before checking the
Hessian. The repair adds an explicit, independently checked acceptance path for
that narrowly eligible endpoint. It does not turn every failed optimization
into a successful integral or claim that the acceptance rules are unchanged.

Recovery requires finite gradient/error evidence from recognized derivative
precision-stop statuses during the search. The endpoint must equal both the last
and best primary objective point, and fresh evaluations must reproduce the
original objective value. Nonnested gradient step schedules, the strict full
Hessian checks, curvature-relative stationarity, a curvature-scale gradient
recheck and symmetric local objective probes must all pass. The original
scientific objective and endpoint are retained throughout.

An accepted integral returns `status="success"`, with
`method_details.precision_recovery.status="accepted"`. That record retains the
nonconverged optimizer's `optimization_status="failed"`, original `failure_reason`
and `warning`. Failed derivative records remain failed, with public `gradient=None`;
their finite candidate estimates are diagnostic evidence only. Acceptance does
not establish optimizer convergence, a global mode or exact nonlinear integration.

Explicit `optimization.stationarity_tolerance` is binding, **including an
explicitly supplied default `1e-5`**. The absolute gradient-plus-error limit is
checked in prior-standardized coordinates, including the mapped-back local
gradient. Omission preserves the optimizer's default absolute check but permits
curvature-relative recovery after the strict eligibility and consistency checks.
The public posterior API preserves omitted versus explicit settings.

The BFGS default remains `min(1e-6, stationarity_tolerance / 10)`, normally
`gtol=1e-6`; the Hessian and stationarity-impact thresholds both remain `1e-3`.
There is no automatic alternate optimizer, multistart, endpoint move, GHQ fallback
or one-effect-only special case. Scientific inputs, priors and normalization are
unchanged. Any failed positive-prior candidate still prevents a complete
posterior: all non-skipped posterior probabilities remain `None`, with no partial
normalization. See the [API contract](../api.md#precision-limited-recovery).
