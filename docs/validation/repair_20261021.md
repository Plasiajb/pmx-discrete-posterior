# Numerical Repair: Scope And Validation Status

**Status: unreleased development repair, not full release acceptance.**
Branch `repair/prior-coordinates-20261021` uses the development identifier
`0.2.1.dev20261021`, based on v0.2.0. This does not announce a new release,
tag or merge to the main branch. The published v0.2.0 tag and artifacts remain
unchanged; existing v0.2.0 documentation and legacy manuscript examples are
retained. Historical repair-source evidence below is distinct from fresh
checks of this branch or its installed artifacts.

## What Changes

Laplace calculations use covariance-standardized coordinates:
`eta = mean + L z`, where `L` is the Cholesky factor of the active-effect
covariance. Optimization and full Hessian evaluation use the same standardized
coordinates, including cross-effect curvature and the log Jacobian
`log(abs(det(L)))`. The original density callback remains in use; the coordinate
change does not replace a custom density with a Gaussian approximation.
All active dimensions, including tiny positive variances, are retained.
User-supplied initial points and returned modes remain in original effect coordinates.

Optimization diagnostics retain SciPy termination details, the returned point
and gradient, last and best primary objective evaluations, and derivative-failure
evidence. These diagnostics expose failures; they do not authorize accepting them.

Scientific model equations, scientific inputs, priors, posterior normalization,
the seven-group public API and independent gradient, Hessian and stationarity
acceptance gates are unchanged. Failed positive-prior candidates still
prevent posterior normalization. This is not a new Hessian or GHQ backend.
No R dependency or automatic retry is introduced; R `aghq` remains an external
comparison.

## Current Search Default

The fourth production change, in `interfaces/inputs/numerical_options.py`, sets
the BFGS default to `min(1e-6, stationarity_tolerance / 10)`. With the default
`stationarity_tolerance=1e-5`, this gives `gtol=1e-6`. A tighter requested
stationarity tolerance can reduce that default; explicit overrides, including
the former `gtol=1e-7`, remain supported. The earlier coordinate, Laplace and
optimization-diagnostic repair files are unchanged by this update.

This changes the search stopping tolerance, not the independent acceptance
gates or derivative settings.

The source default-update focused regression recorded **250 passed**, covering
the new default, explicit former tolerance, tighter requested stationarity and
unchanged independent checks. The subsequent complete repair-source regression
recorded **1427 passed, two Windows symlink-permission skips, zero failures**.
Its receipt is identified as `repair/default_gtol_full/20261021T011459_6d689f29`.
Six copied historical-document links failed in the first full run; they were
corrected without changing production code or tests, followed by 12 navigation
test passes and the complete rerun. Those local historical links are not imported
into this repository. Test groups overlap; do not add these counts.

## Historical gtol Comparison

**Before the default change, `gtol=1e-7` calls failed on BFGS precision loss in
TAC c036 and c037.** Each warning concerned the candidate history with 6 mg at
0 h and the 12 h dose missed. No failed candidate was dropped or bypassed.

A local repair-source experiment on 2026-10-21 made two actual full package calls
per case: one with `gtol=1e-7` and one with explicit `gtol=1e-6`, four calls total.
The latter returned complete posteriors directly through `compute_posterior`,
without external replacement integrals or ignored warnings. These calls preceded
the production default update and are configuration evidence for its selection.

| Case | Former setting `gtol=1e-7` | Explicit `gtol=1e-6` | Maximum posterior difference from prior external vector |
| --- | --- | --- | ---: |
| TAC c036 | Precision loss; no complete posterior | 4/4 candidates succeeded; complete posterior | `2.639003821e-9` |
| TAC c037 | Precision loss; no complete posterior | 4/4 candidates succeeded; complete posterior | `5.871017728e-9` |

The comparison vectors came from the earlier independently validated external
saved-endpoint workflow, **not the historical `gtol=1e-7` calls, which produced
no complete posterior**. Candidate identities and priors were matched; complete rankings
were unchanged. All eight candidates under the explicit setting passed the
original independent checks: gradient-envelope threshold `1e-5`, Hessian-impact
threshold `1e-3` and stationarity-impact threshold `1e-3`. These are numerical
screens, not rigorous bounds on Laplace approximation error.

With a prepared model, data, observations, candidate states and priors, this
pins the successful comparison setting. It now matches the production default
when using the default stationarity tolerance; explicit `gtol=1e-7` is still
supported for comparisons.

```python
from pmx_discrete_posterior import compute_posterior

result = compute_posterior(
    model=model,
    individual_data=individual_data,
    observations=observations,
    candidate_states=candidate_states,
    priors=priors,
    integration_method="laplace",
    numerical_options={"optimization": {"backend_options": {"gtol": 1e-6}}},
)
if result["status"] != "success":
    raise RuntimeError(result["failure_reason"])
```

[SciPy 1.16.2 BFGS documentation](https://docs.scipy.org/doc/scipy-1.16.2/reference/optimize.minimize-bfgs.html)
suggests considering a higher `gtol` after precision-loss termination; this is
not a requirement and does not prescribe `1e-6` for these cases.

The two-case comparison motivated the default change but does not establish
fresh new-default five-repeat validation or a full-matrix rerun. The historical
132/135 TAC package-run count and its original failure records remain unchanged.

OXC c026 and TAC c078 are deferred near-zero-residual cases. The 14 dashboard
exclusions concerning covariance-tail and occasion-boundary compatibility are
separate issues and are not resolved by this numerical repair.
